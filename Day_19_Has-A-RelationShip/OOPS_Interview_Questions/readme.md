
# 🚀 Java Interview Questions & Answers (Part 2)

1  What is Java?

Java is a high-level, object-oriented, platform-independent programming language developed by Sun Microsystems in 1995 and currently owned by Oracle Corporation.
Java follows the principle of **Write Once, Run Anywhere (WORA)** because Java source code is compiled into bytecode, which can run on any operating system that has a Java Virtual Machine (JVM).

--
 Is Java Fully Object-Oriented ?
   
   No.
Java supports primitive data types like int, char, float, boolean etc., so it is not considered 100% object-oriented.

---
# Why Java?

Java is widely used because it is platform-independent, secure, object-oriented, robust, portable, scalable, and has a huge community with extensive libraries.

---
#  What is WORA?

WORA stands for **Write Once, Run Anywhere**.

It means a Java program is written and compiled only once, and the generated bytecode can run on any operating system that has a Java Virtual Machine (JVM).

This is one of the biggest advantages of Java.
---

# Why is Java Platform Independent?

Java is platform independent because it generates **Bytecode** instead of machine code.

The JVM present on every operating system converts bytecode into machine code.

Therefore, the same Java program works on different operating systems without recompilation.

---
# What is JVM?

JVM stands for **Java Virtual Machine**.

It is a virtual environment that converts Java Bytecode into Machine Code and executes Java programs.
--

### Q2. Is JVM Platform Independent?
No.

Each operating system has its own JVM implementation.

# What is JRE?
JRE stands for **Java Runtime Environment**.

It provides the environment required to run Java applications.

JRE contains:

- JVM (Java Virtual Machine)
- Core Java Libraries
- Supporting Files

# What is JDK?

## ---- ⭐⭐⭐⭐⭐

JDK stands for **Java Development Kit**.

It is a complete package used to develop, compile, and run Java applications.

JDK contains:

- JRE
- JVM
- Java Compiler (javac)
- Development Tools

# Question 11

# What is Bytecode?


Bytecode is the intermediate code generated by the Java Compiler (javac) after compiling a Java source file (.java).

It is platform-independent and executed by the JVM.

---

## Detailed Explanation

Java source code cannot be understood directly by the computer.

The Java Compiler converts:

```text
Test.java

↓

Test.class
```

The `.class` file contains **Bytecode**.

Later, JVM converts Bytecode into Machine Code according to the Operating System.

---

## Flow Diagram

```text
Java Program (.java)

↓

Java Compiler

↓

Bytecode (.class)

↓

JVM

↓

Machine Code

↓

Output
```

---

## Real-Time Example

Suppose you develop an Online Shopping Application.

Compile once.

The generated Bytecode can run on:

- Windows
- Linux
- macOS

using their respective JVMs.

---

## Telugu Easy Understanding 🇮🇳

Teacher writes notes in English.

English notes are understood everywhere.

Similarly,

Bytecode is a common language.

Every JVM understands Bytecode.

---

### Q3. Is Bytecode Machine Code?

## Quick Revision

Bytecode is the platform-independent intermediate code generated by the Java compiler and executed by the JVM.

# Question 12

# What is Class Loader?

## ---- ⭐⭐⭐⭐⭐

Class Loader is a JVM component that loads Java class files (.class) into memory before execution.

---

## Detailed Explanation

When you execute:

```text
java Test
```

JVM first asks the Class Loader to locate and load the required class into memory.

Only after loading,

the JVM executes the program.

---

## Class Loading Process

```text
.class File

↓

Class Loader

↓

Memory

↓

JVM Execution

↓

Output
```

---

## Types of Class Loaders

### Bootstrap Class Loader

Loads Java Core Classes.

Example:

```java
java.lang.String
```

---

### Extension (Platform) Class Loader

Loads Java Extension Libraries.

---

### Application Class Loader

Loads User-Defined Classes.

Example

```java
Student.class

Employee.class
```

---

## Real-Time Example

When you execute

```text
java Student
```

The Application Class Loader loads Student.class into memory.

---

## Telugu Easy Understanding 🇮🇳

Think of a librarian.

Before reading a book,

the librarian first brings the book.

Similarly,

Class Loader brings the class into memory before execution.

---

## Interview Follow-up Questions

### Q1. Does JVM execute classes directly?

Answer

No.

Class Loader loads them first.

---

### Q2. How many Class Loaders are there?

Answer

Three.

- Bootstrap
- Platform
- Application

---

## One-Line Interview Answer

Class Loader is a JVM component responsible for loading class files into memory before execution.

# Question 13

# What is Garbage Collection?

## ---- ⭐⭐⭐⭐⭐

Garbage Collection is the automatic process of removing unused objects from memory.

It helps free memory automatically.

---

## Detailed Explanation

When an object is no longer referenced,

it becomes eligible for Garbage Collection.

JVM automatically removes it.

This prevents memory wastage.

---

## Diagram

```text
Object Created

↓

Object Used

↓

Reference Lost

↓

Garbage Collector

↓

Memory Freed
```

---

## Real-Time Example

```java
Student s = new Student();

s = null;
```

The Student object becomes eligible for Garbage Collection.

---

## Telugu Easy Understanding 🇮🇳

Imagine your room.

Old newspapers are no longer useful.

Your mother throws them away.

Similarly,

Garbage Collector removes unused objects.

---

## Advantages

✔ Automatic Memory Management

✔ Prevents Memory Leaks

✔ Improves Performance

✔ No Manual Memory Deallocation

---

## Interview Follow-up Questions

### Q1. Who performs Garbage Collection?

Answer

JVM.

---

### Q2. Does Java have automatic memory management?

Answer

Yes.

---

## One-Line Interview Answer

Garbage Collection automatically removes unused objects from memory.

# Question 14

# Can We Call Garbage Collector Manually?

## ---- ⭐⭐⭐⭐⭐

Yes.

We can request Garbage Collection using:

```java
System.gc();
```

or

```java
Runtime.getRuntime().gc();
```

However,

there is **no guarantee** that Garbage Collection will execute immediately.

It is only a request to the JVM.

---

## Detailed Explanation

Calling

```java
System.gc();
```

does not force JVM to run Garbage Collection.

The JVM decides when it is appropriate.

---

## Interview Follow-up Questions

### Q1. Is System.gc() compulsory?

Answer

No.

---

### Q2. Does JVM always execute it?

Answer

No.

---

## One-Line Interview Answer

System.gc() only requests the JVM to perform Garbage Collection; execution is not guaranteed.
